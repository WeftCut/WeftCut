## Upgrading from 0.8

**Projects open by their project file.** A project is still its folder, but its
file is now `project.wcpr` (it was `project.json`), and a pack is a `.wcpk`.
**Open project…**, on the start screen and in the File menu, picks either one:
a `.wcpr` opens its project, a `.wcpk` is unpacked into a new folder you
choose. Projects in your Recent list open as before.

**Double-click a `.wcpr` or `.wcpk` to open it in WeftCut**, on Windows, macOS
and Linux. Installing or updating to 0.9 registers both types; the AppImage
registers them the first time it runs.

**A 0.8 project can no longer be opened by 0.8 once 0.9 opens it**, even
without an edit: its `project.json` is renamed to `project.wcpr`. To keep using
a project in 0.8, copy its folder before opening it here. The original stays
beside it as `project.pre-v7.json`. To open a 0.8 project that is not in Recent,
pick *WeftCut 0.8 project (project.json)* in the Open project dialog.

**Motifs live in the project folder.** A project keeps its own copy of every
Motif it uses under `Motifs/`, so a copied or packed project plays the same on
another computer. Opening a 0.8 project copies its Motifs in once. The Motifs
panel lists *This project* and *Library*: placing a library Motif copies it in,
and a later library change reaches a project only when you choose **Update
project copy**. Motif drafts are gone: agents create and edit the open
project's Motifs directly, and **Save to library** offers one back to the
library. Your old drafts stay where they were: a notice counts them and opens
their folder, and an agent can bring one into a project. A Motif an opened
project cannot find shows as missing; the upgrade line in the log names the
draft that restores it.

**A Motif runs only when you trust it on this computer.** Motifs placed from
your library or made here are trusted. One that arrives in a project, a ZIP or
a folder from elsewhere shows *Not trusted* and draws a placeholder until you
select it and press **Trust**. Its card lists what the Motif's files contain;
you can ask an agent to read them first.

**Audio edges sit on frames.** Every clip edge, audio included, now falls on a
video frame, so linked picture and sound always cut together. Fine sync still
moves by single samples, sliding the sound inside its clip. A project with
audio cut between frames is repaired when it opens, keeping each sound where it
played. The inspector's audio units selector is gone.

## What's new

- **Pack project…** (File menu) writes the project folder into one `.wcpk`
  file to move or archive it; **Open project…** unpacks it into a new folder.
- **Check portability…** (File menu) lists what the project still takes from
  outside its folder: media, Motifs and fonts.
- **Fonts travel with the project**: every font a project uses is copied into
  its `Fonts/` folder. A family can be left out in the project settings, under
  **Fonts**.
- New projects get a `.gitignore` that leaves out caches, backups, logs and
  exports.
- **Motif version history**: the library keeps every version of a Motif, and
  its card restores an older one. Deleting a Motif moves it to the trash.
- **Audio crossfades**: a transition at a cut between linked clips also
  crossfades their sound. Agents can crossfade two audio clips on one track.
- **Delete start to playhead (Q)** and **Delete end from playhead (W)** cut the
  clip under the playhead and close the gap on that side, in one undo.
- **Faster export on Windows**: export no longer runs at the display's refresh
  rate.
- **Agent panel**: in the editor, the status row folds into the tab bar; the
  service dot opens the connection details.
- **Save As** always makes a new folder and never writes into an existing one.
- **Fixes**: BT.2020 and HDR sources look the same in preview and export; the
  preview survives a GPU process restart; follow playhead stops while you
  scroll away; a reopened project shows the timeline you left; clicking a
  keyframe selects its clip; ripple closes linked cuts at 29.97 and 59.94 fps;
  the system keyring is asked only when a cloud key is saved or read.
